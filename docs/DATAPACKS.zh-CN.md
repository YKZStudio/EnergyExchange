# 数据包规则

[English](DATAPACKS.en.md) · [返回首页](../README.md)

每个物品使用一个文件：`data/<物品命名空间>/energyexchange/values/<物品路径>.json`。例如 `minecraft:diamond` 对应 `data/minecraft/energyexchange/values/diamond.json`，`othermod:materials/dust` 对应 `data/othermod/energyexchange/values/materials/dust.json`。

启用定价：

```json
{ "value": "8192" }
```

禁用：

```json
{ "enabled": false }
```

| 字段 | 规则 |
| --- | --- |
| `value` | 启用时必填。十进制**字符串**，范围 1 至 `10^128−1`；禁止数字类型、小数、指数、正负号、空白、前导零 |
| `enabled` | 可选布尔值，默认 `true`。为 `false` 时不能同时指定 `value` |

不支持未知字段；每个文件最多 4096 字符，最多 16384 个规则资源，完整物品 ID 最长 256 字符。JSON 使用 UTF-8。未知模组的物品 ID 可以保留在数据包中，但只有已注册且启用的物品能实际兑换。

## 覆盖与热重载

1. 将[示例数据包](../examples/value-overrides)整个文件夹复制到 `<世界>/datapacks/`；`pack.mcmeta` 应位于该文件夹根目录。
2. 修改圆石规则中的 `value`；示例同时禁用钻石。
3. 管理员执行 `/reload`，必要时使用 `/datapack list` 检查启用状态。
4. 手持圆石执行 `/ee value` 验证价格。恢复默认值时删除覆盖文件并再次重载；若要禁止底层默认规则，请使用 `enabled:false`，不能只删除文件。

Minecraft 的正常数据包优先级决定**同一资源位置**的胜者；高优先级文件整体替换低优先级文件，不合并字段。不以文件遍历顺序决定价格。不同物品互不影响。v0.1 不支持标签批量定价或配方自动推导。

加载器先解析全部有效资源，再发布不可变价格表。重载过程中停止交易；任何无效规则令重载失败，并锁定交易，直到修复后成功重载。启动时无效规则按正常数据包加载错误处理；不要将错误规则默默降级为免费物品。

已学知识不依赖当前价格。禁用物品后知识保留，但不能再分解、学习或兑换。改价只影响后续交易，不追溯调整玩家余额；运营服务器应避免不受控的短期改价套利。服主负责数据包以及其他模组配方的经济平衡。

## 组件策略

规则只指定物品 ID，不能放宽默认组件限制。即使为潜影盒、药水、工具、书等设置价格，也只接受与全新默认物品组件相同的样本，且只产出默认物品。任意组件兑换需要后续独立设计，不能通过 `allow_nbt` 等字段启用。
